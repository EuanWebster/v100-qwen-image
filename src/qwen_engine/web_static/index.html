    Engine & performance

    Recipe Quality uses the reference model at the step count you choose — the slowest, most faithful option. Turbo uses the Turbo image model (with the same text encoder and decoder as Quality) and always runs its fixed 8 sampling steps: drawing is about five times faster, but loading the model and reading your prompt dominate a whole run, so the total is often only slightly shorter. Turbo has no negative prompt and no guidance (CFG 1.0), and runs in FP16 only.

                    Help

                    Backend status
                    This page talks only to the local qwen-web server on the same origin, when it is running. Opened over file:// or without that server it is disconnected: planning and authoritative validation are unavailable. Real generation requires explicit server enablement.
                    Generation gates
                    Unknown until the server answers: adapter, hardware, assets and calibration gates are reported by /api/v1/status. Asset and hardware checks run per job; exact calibration preflight is not wired into generation.
                    Generation
                    Planning and authoritative config validation come from the local server; generation uses the engine through a serial job queue when enabled by the server operator.
                    Runtime paths & model files
                    Runtime paths (output, cache, log, benchmarks, models, manifest) belong to the server's own configuration and can never be set from this page; the editable-config export omits them. Settings → Models can download model files, but only from the catalogue this server was built with: the page sends ids, never URLs or paths. Files are written to the server's own models dir — which the card names, next to the size of each download — and a download can be cancelled at any time; files already fetched stay put and the next Download resumes with the rest. Until every required model is installed, generation stays disabled. Nothing is downloaded without a press of Download.
                    Validation of full settings
                    What this page checks is a lightweight form check only, not a fitness or memory check. The local server performs the authoritative GenerationConfig validation when it is reachable.
                    Privacy
                    This page makes no third-party requests and loads no external fonts, scripts or analytics; its only requests are same-origin calls to the local server. The only thing the browser stores is your chosen theme (Original, Neon or Paper), kept under one local key; your prompt, draft and settings are never saved by the browser. Plain static hosting serves these files but enforces nothing by itself — locality is controlled by the qwen-web server's explicit bind addresses. Remote access uses the LAN or Tailscale address selected by the operator.
                    History
                    Each finished job stores one small job.json file inside its own output folder holding its settings, state and image checksum. History is rebuilt from those files at server start, so completed images reappear after a restart. An image whose file no longer matches its checksum is never served: the entry stays listed with its image marked unavailable, so you can still read its settings and forget it. "Forget entry" deletes that one job.json and nothing else, so the image file stays on disk and the entry stays gone after a restart.
                    Drafts
                    Nothing is saved by the browser automatically except the theme choice above. Prompts, seeds and form values are never stored; an opt-in draft store for validated form values may come later.
